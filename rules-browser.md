Agents reach the owner's signed-in Chrome only through the DevTools bridge in `tools/browser_bridge/` (full instructions in its `README.md`). Do not use a tool's own browser extension, such as Claude in Chrome: the bridge enforces the one-agent-per-site rule, and an extension bypasses it. Open your own tab rather than taking over one the owner is using. Browser work is the most expensive thing an agent does, so prefer a free API or a direct image URL to clicking through a site.

- **The bridge:** check `curl -s http://127.0.0.1:9333/ping` (the port is `bridge.port` in `project.json`). Start the daemon only if it is not running and the owner has said agents may start it; never open a fresh DevTools session per action. The owner approves Chrome's remote-debugging prompt for each new connection, so never restart the live daemon or start a test daemon against the owner's Chrome without asking. If a request fails with "Chrome is not connected", stop, record a failed retrieval and ask the owner to click Allow, rather than retrying. Agents work only in the Chrome profile named in `project.json`, and the daemon refuses a tab that opens in another profile. Set `BRIDGE_AGENT` to your name (`gemini`, `claude`, or a subagent's name such as `claude-sub-1`), claim each site before using it, and release it when you finish. If `/ping` does not report `"version": 2`, the running daemon does not enforce site claims; do not run agents in parallel until it has been updated.
- **No waits for a stable page.** FamilySearch, Archion and ScotlandsPeople change the page continuously, so navigate with `client.navigate(..., wait_sec=3)`. Wrap JavaScript as an arrow function, for example `() => document.body.innerText`.
- **Read the site notes first.** `tools/browser_bridge/site-notes.md` records what earlier runs learned about the sites and viewers, and the films already mapped (image-to-year and Bild-to-page pairs); give its relevant parts to any subagent, and add what you learn, dated.
- **Prefer text to screenshots**; keep screenshots for handwriting, headstones and saving images.
- **FamilySearch:** image pages are `https://www.familysearch.org/ark:/61903/3:1:<id>`. Use the bridge's `download_fs` for full images rather than the viewer's download button, and move files into `sources/` with descriptive names. Full-text search works by URL, for example `https://www.familysearch.org/search/full-text/results?q.fullName=%2B"John Smith"&q.text=%2BBoston`; its machine reading of handwriting is rough, so a miss is not proof of absence.
- **Ancestry:** one search request per call, 5 to 10 seconds apart. Never treat zero results during throttling as a negative finding.
- **Sign-outs:** restarting Chrome can sign the owner out of FamilySearch and other sites, and signed-out searches return partial results. If a session has dropped, ask the owner to sign in again, and do not record the partial results as negative.
- **If the browser fails two or three times in a row, stop** and tell the owner what you tried.
